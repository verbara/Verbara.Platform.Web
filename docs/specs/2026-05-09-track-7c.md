## Problem

Verbara has end-to-end backend support for embedded WebChat (REST endpoints `/api/v1/webchat/sessions`, native WebSocket transport `/ws/webchat/{sessionId}`, channel infrastructure with `WidgetKey` + `AllowedOrigins` configurable per-tenant). What's missing: **the actual widget that customers embed on their websites**. The admin scaffold at `src/admin/webchat/webchat-page.tsx` shows a copy-paste snippet pointing to `webchat-widget.js` — but the script doesn't exist.

This track is the final track of the v1.14.x → v3.0.0-web Operational Foundation roadmap. With Tracks 1-6 closed and Tracks 7A/7B done, only Track 7C remains. It is greenfield — a customer-facing product, not an internal admin feature.

After deeper audit (see Brainstorming session 2026-05-09), the originally-proposed "MVP scope" was too narrow — it would have produced a tech demo, not a product. A real enterprise webchat widget in 2026 has table-stakes features that cannot be skipped without making the widget commercially unusable: pre-chat form, visitor persistence, mobile responsive, markdown rendering, browser title flash, office hours indicator, programmatic SDK API, inline media reception, accessibility baseline, visitor page context, conversation timeout UX, sound notification.

## Goals

1. **Producto real, no tech demo.** A tenant can embed the SDK on their site, configure name/email collection, theme it, deploy to production, and have visitors connect to agents who can respond from the existing admin app.
2. **Hybrid architecture per the original 2026-05-03 sketch:** vanilla JS SDK for the host page (~8-12 kB gzip) + React iframe app for the chat UI (lazy-loaded only when opened).
3. **WebSocket transport** (corrected from the earlier sketch's "SignalR"; backend uses native WebSocket at `/ws/webchat/{sessionId}`).
4. **Same-origin distribution** for v3.0.0; CDN migration deferred. Assets at `https://<domain>/webchat/v1/...` served by existing nginx.
5. **WCAG 2.1 AA baseline** inheriting Track 5C-a11y patterns.
6. **3 locales** (en-US, es-419, pt-BR) via separate `webchat` i18n namespace.
7. **Single release** at `v3.0.0-web` (Option A — closes Nivel 7 + the entire roadmap in one major bump).

## Out of Scope (explicit)

This is a comprehensive MVP, not "everything possible." Deferred:

1. **Visitor file uploads.** Receiving agent-sent files is in scope; visitors uploading is not.
2. **Voice/video.** Separate product surface; not webchat.
3. **Bot routing.** Backend has BotBasic but integration through the widget (qualifying questions before agent) is a follow-up — adds significant flow complexity.
4. **NPM package of the SDK.** Script-tag-only delivery for v1; NPM defer until host integrations request it.
5. **Mobile-native SDK.** iOS/Android apps embedding the chat are out of scope.
6. **Service Worker offline.** localStorage queue covers 80% of offline scenarios; SW adds complexity for diminishing returns.
7. **External CDN.** Same-origin via existing nginx for v3.0.0. CDN migration is operational work tracked separately.
8. **Plan feature gating.** Backend `PlanFeature` enum doesn't have `WebChat`; without backend change, gating is moot. Future track if needed.
9. **CSAT rating prompt** (post-conversation 1-5 stars). Tier 2 nice-to-have, but adds Survey integration complexity. Defer.
10. **Message delivery receipts** (Sent/Delivered/Read). Defer — backend may not emit per-message acknowledgments yet.
11. **Quick replies / suggested actions.** Buttons sent by agent that visitor clicks. Defer — agent UI changes required.
12. **Email transcript export.** Defer — backend has email infrastructure but no per-conversation export endpoint visible.
13. **Multi-tab BroadcastChannel sync.** Each tab gets independent session; defer cross-tab consolidation.
14. **CAPTCHA / spam protection.** Backend rate limiting suffices for v1. Defer CAPTCHA.
15. **Message moderation / profanity filter.** Defer — backend concern.
16. **GDPR self-service deletion.** Defer — admin has retention policy; visitor self-service deletion is a separate flow.
17. **Cookie consent integration.** Widget uses localStorage (not cookies) so it sidesteps most cookie-banner concerns. Document this in README.
18. **Iframe-restricted hosts fallback.** Hosts that block iframes via CSP `frame-src` directive will not load the widget. Document the CSP requirement in README; no graceful fallback in v1.
19. **A/B-testing variants** (different greetings, positions, etc.). Out of scope.
20. **Verbara-internal customer dashboards** (visitor analytics, conversation reports embedded in the widget). Out of scope; the admin app already has analytics.

### Build pipeline

**SDK config (`vite.webchat-sdk.config.ts`):**

- Entry: `src/webchat/sdk/index.ts`
- Output: `public/webchat/v1/verbara-webchat.js`
- Format: IIFE (compatible with `<script>` tags, no module syntax)
- Minify: terser with aggressive settings (mangle props matching `^_`)
- No external React (vanilla JS)
- Target: modern browsers (ES2020+) — IE11 not supported per `package.json` browserslist already

**Embed config (`vite.webchat-embed.config.ts`):**

- Entry: `src/webchat/embed/main.tsx`
- Output: `public/webchat/embed/`
- App mode (HTML + assets)
- React 19, but separate bundle (does NOT share chunks with admin app — different deployment)
- Tailwind v4 reused via `@tailwindcss/vite` plugin with `content: ['src/webchat/**/*']`

**Top-level scripts:**

```json
"scripts": {
  "build": "tsc -b && vite build",
  "build:webchat-sdk": "vite build --config vite.webchat-sdk.config.ts",
  "build:webchat-embed": "vite build --config vite.webchat-embed.config.ts",
  "build:webchat": "npm run build:webchat-sdk && npm run build:webchat-embed",
  "build:all": "npm run build && npm run build:webchat",
  "dev:webchat-demo": "vite preview --port 4173 --outDir public/webchat/embed"
}
```

### Transport (corrected from earlier sketch)

Backend uses **native WebSocket** at `/ws/webchat/{sessionId}`, NOT SignalR. Earlier spec was wrong.

`src/webchat/embed/transport/ws-client.ts` implements:

- Connect to `wss://...` after session creation returns `wsUrl`
- Auto-reconnect with exponential backoff (1s → 30s)
- Heartbeat ping every 30s; disconnect detection on missed pong
- Outgoing messages: JSON `{ type: 'message', body: string }` (confirm protocol at implementation; backend audit shows REST shape, WS shape needs verification)
- Incoming events: `{ type: 'message' | 'typing' | 'agent-joined' | 'agent-left' | 'session-ended', ... }`
- On disconnect: queue outgoing in localStorage, replay on reconnect

### Visitor identity

- On first SDK init: generate `visitorId = crypto.randomUUID()`, store in `localStorage` under `verbara-webchat-visitor:<tenantId>`.
- On subsequent inits: reuse the existing `visitorId`.
- `visitorId` sent on session creation; backend correlates returning visitors.
- Visitor name + email stored alongside `visitorId` once entered in pre-chat form (so returning visitor doesn't re-enter).
- "Reset" button in widget settings clears localStorage for this tenant (privacy escape hatch).

### Mobile responsive

Breakpoint at 600px width:

- Above: corner widget (380×600px max).
- Below: full-screen takeover (`position: fixed; top: 0; left: 0; width: 100vw; height: 100vh; z-index: 2147483647`).
- Bubble disappears in full-screen mode (close button in widget header replaces it).

### Markdown sanitization

Reuse the safe-render pattern from Track 4D (`qa-detail-drawer.tsx`'s `renderMarkdown`). Whitelist: `p`, `strong`, `em`, `code`, `br`, `a` (with `rel="noopener noreferrer"` enforced). Code spans rendered with monospace font. Links open in new tab.

### Theming

CSS custom properties at iframe `:root`:

```css
:root {
  --vw-primary: #0d9488;
  --vw-primary-foreground: #ffffff;
  --vw-bg: #ffffff;
  --vw-fg: #0f172a;
  --vw-border: #e2e8f0;
  --vw-muted: #64748b;
  --vw-radius: 0.75rem;
  --vw-font: 'Inter', system-ui, sans-serif;
}
```

SDK init applies overrides via inline `<style>` injected into iframe document head. Tenant-level config fetched from `GET /api/v1/webchat/config?tenantId=...` — if endpoint returns 404, defaults stand.

### nginx routing

Add to existing `nginx.conf`:

```nginx
location /webchat/v1/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
    try_files $uri =404;
}
location /webchat/embed/ {
    add_header Cache-Control "public, max-age=300";
    add_header X-Frame-Options "SAMEORIGIN";
    add_header Content-Security-Policy "default-src 'self'; connect-src 'self' wss:; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'";
    try_files $uri /webchat/embed/index.html;
}
location /webchat/demo.html {
    add_header Cache-Control "no-cache";
    try_files $uri =404;
}
```

### CDN strategy (deferred)

Same-origin for v3.0.0. Future: CloudFlare or S3+CloudFront. Path versioning (`/webchat/v1/`, `/webchat/v2/`) preserved in the design so CDN migration is a config change, not an API break.

### i18n separation

Iframe app initializes its own i18next instance with `ns: ['webchat', 'common']` only. The admin app's i18n instance is unaffected. Keys are loaded from `public/locales/<locale>/webchat.json` via `i18next-http-backend`.

The admin's i18n parity script (`scripts/i18n-parity-check.mjs`) extends to validate the `webchat` namespace too.

| Risk                                                                                   | Likelihood | Mitigation                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `GET /api/v1/webchat/sessions/{id}/messages` (history) may not exist for resume        | M          | Same as above. If missing, restore from localStorage cache only on resume; document.                                                                                                                      |
| Shadow DOM not supported in older browsers                                             | L          | Browserslist already excludes IE; Safari 14+ has Shadow DOM. Acceptable.                                                                                                                                  |
| Iframe origin mismatch breaks postMessage                                              | M          | Strict targetOrigin validation; thorough tests for cross-origin scenarios.                                                                                                                                |
| Visitor's host site has CSP that blocks iframe                                         | M          | Document CSP requirements in README. Cannot bypass — host must allowlist `frame-src`. Graceful fallback (show message in bubble: "Chat unavailable due to site security settings") deferred to follow-up. |
| Bundle size exceeds budget (180 kB gzip iframe)                                        | M          | React itself + transport are heavy. Lazy-load message virtualization lib (`@tanstack/react-virtual` already in deps). If exceeds, drop optional features (markdown lib alternatives, etc.).               |
| WebSocket reconnect storms during partial outages                                      | L          | Exponential backoff caps at 30s; backend should handle reconnect floods; if not, document and rate-limit client-side.                                                                                     |
| LocalStorage quota exceeded after many sessions                                        | L          | Cap message history at 100 most recent per session in localStorage; backend remains source of truth.                                                                                                      |
| Sound notification annoys users                                                        | L          | Default OFF until user explicitly opts in via UI toggle.                                                                                                                                                  |
| Theme primary color fails contrast                                                     | M          | Computed contrast check at theme apply; if < 4.5:1 against background, log dev warning. Don't block — tenants own their theme.                                                                            |
| Multi-tab same visitor opens 2 widgets, sends 2 messages                               | M          | Each tab has own session (acceptable behavior for v1). | `<style>` injection into iframe document interferes with theme application order       | L          | Apply theme variables in `:root` of iframe document, after default stylesheet. Computed cascade resolves correctly.                                                                                       |
