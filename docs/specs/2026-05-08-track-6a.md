# Track 6A — i18n Expansion: Phone + Timezone + Currency

**Version:** 2.3.0 (closes Nivel 6 "i18n Expansion")
**Status:** Draft (pending user review)
**Created:** 2026-05-08
**Predecessor:** [Track 5D](2026-05-08-track-5d.md) (closed `v2.2.0-web`)
**Roadmap entry:** [`docs/plans/active/2026-05-03-v1.14.x-operational-foundation-roadmap.md`](../plans/active/2026-05-03-v1.14.x-operational-foundation-roadmap.md) §Nivel 6 → Track 6A

## Problem

Three i18n-shaped gaps remain after Nivel 5 closes:

1. **Phone numbers are unformatted strings.** 45 display sites + 1 input site (`wrap-up-dialog`'s `<Input type="tel">` with placeholder `+1234567890`) treat phones as raw strings. Zero validation regexes. A user typing `9255550100` sees no country detection, no formatting feedback, no validation. Display sites concat raw E.164 with no formatting (e.g., `+19255550100` instead of `+1 (925) 555-0100`).
2. **Timezone handling is scattered and incomplete.** Three input surfaces today: campaign schedule-step uses a hardcoded 10-zone `<select>` (only US zones + UTC); contact-info and notification-rule use `<Input type="text">` with placeholder "UTC" — accepting any string. Browser auto-detect missing. `useFormatDate` does NOT consume timezone — a supervisor in GMT-5 sees timestamps in browser-local time, never in event-source time.
3. **Currency formatter has 6 raw `toFixed()` holdouts** in billing/quotas + bot-form despite ~85% adoption of `formatCurrency` across billing/revenue.

The roadmap originally also called for an "address picker per-country" but the audit found:

- Backend stores `contact.addresses = { channel, address }[]` — opaque strings, not structured fields
- ZERO forms collect addresses today (only API-loaded read-only display)
- Implementing a country-aware address picker without backend schema support would solve a problem that doesn't exist

This is the closure track for Nivel 6.

## Goals

1. **Phone formatter foundation** — `useFormatPhone()` hook + `<PhoneInput>` primitive backed by `libphonenumber-js/min`. Always emits E.164 to consumers; displays locale-formatted text. Validates country-aware.
2. **Timezone selector foundation** — `<TimezoneSelect>` primitive using `Intl.supportedValuesOf('timeZone')` (~440 IANA zones). Browser auto-detect via `Intl.DateTimeFormat().resolvedOptions().timeZone`. Filterable combobox grouped by region.
3. **`useFormatDate` accepts optional `timezone` argument** — passes to `Intl.DateTimeFormat({ timeZone })`. Default unchanged (browser-local) for backward compat.
4. **Migrate scattered usages** — 3 timezone input surfaces, phone input in wrap-up + ~10 high-priority phone display sites, 6 raw currency cases.

## Out of Scope (explicit)

- **Address picker per-country.** Backend doesn't store structured addresses; UI has no address forms. Re-evaluate as separate track when backend schema lands or billing flows demand it.
- **Country flag icons** (would add `country-flag-icons` dep ~50 kB). Phone input shows country dial-code text (e.g., `+1 US`).
- **Per-user (server-side) timezone preference.** Already deferred per backend roadmap; user-level preference is a future cross-cutting track.
- **Per-tenant default country setting persisted in tenant.metadata or similar.** First release uses a hardcoded fallback `'US'` with documented follow-up note. The hook accepts an explicit override prop.
- **libphonenumber-js full metadata build** (~25 kB gzip). Track 6A uses `/min` (~7 kB gzip) — supports AsYouType + isValidPhoneNumber across all countries with reduced metadata.
- **Multi-language phone country labels.** Country names in TimezoneSelect/PhoneInput shown in English (e.g., "US", "MX", "AR") — Tier 3, low ROI.
- **Bulk phone display migration of all 45 sites.** Tier 2 stretch covers the highest-traffic ~10. Remaining sites are noted in a follow-up file but defer to a future patch — they keep raw display until adopted.
- **Form-level error summary integrating phone + timezone validation.** Already deferred from 5C-a11y.

## Architecture

### Unit 1 — `src/core/i18n/use-format-phone.ts` + lazy engine module

Phone formatting consumed via a hook. The actual `libphonenumber-js/min` import is lazy-loaded inside the hook to keep eager bundle small. Pattern mirrors Track 5C-export's `<PdfDownloadButton>` lazy import.

```ts
// src/core/i18n/phone-engine.ts — lazy-imported, never re-exported eagerly
export { AsYouType, parsePhoneNumber, isValidPhoneNumber } from 'libphonenumber-js/min';
export type { CountryCode } from 'libphonenumber-js/types';
```

```ts
// src/core/i18n/use-format-phone.ts
interface UseFormatPhoneResult {
  /** Best-effort format. Returns `raw` if parse fails. */
  formatPhone: (raw: string, country?: string) => string;
  /** Returns null if unparseable. E.164 always present on success. */
  parsePhone: (raw: string) => { country?: string; national: string; e164: string } | null;
  /** Validates against country if provided, else permissive (any country). */
  isValidPhone: (raw: string, country?: string) => boolean;
  /** Default country for parsing — read from tenant settings or 'US' fallback. */
  getDefaultCountry: () => string;
}

export function useFormatPhone(): UseFormatPhoneResult {
  /* ... */
}
```

**Note on lazy import:** Hook returns synchronous-looking functions but internally each function awaits the engine module on first call and caches. To keep API synchronous, the hook does an eager-on-first-render `await import` via `useEffect`. If a consumer calls `formatPhone` before the engine is loaded, it returns the raw input as-is (no-op). Acceptable because phone formatting is presentational.

Alternative considered: make the hook async and require Suspense. Rejected — too disruptive for ~50 consumer sites.

### Unit 2 — `src/core/ui/phone-input.tsx`

```tsx
type ButtonVariant = ComponentProps<typeof Input>['variant'];

interface PhoneInputProps extends Omit<
  ComponentProps<typeof Input>,
  'type' | 'value' | 'onChange'
> {
  readonly value: string; // E.164 controlled
  readonly onChange: (e164: string) => void;
  readonly defaultCountry?: string; // default reads from useFormatPhone().getDefaultCountry()
  readonly placeholder?: string;
}
```

Behavior:

- Renders `<Input type="tel">` with the formatted display value.
- Internal state holds the AsYouType-formatted text; on every keystroke, re-runs AsYouType, calls `onChange(parsedE164)` to consumer.
- If user pastes raw E.164 (e.g., `+19255550100`), formatter detects country and beautifies on next render.
- Validation: triggers `aria-invalid` when consumer marks the field invalid via `aria-invalid` prop (or via Zod error from `useFieldA11y` integration).

Lazy library load: AsYouType class is imported in a `useEffect` on mount; until then, the input is a passthrough (raw value displayed). This is invisible because the engine loads in microseconds during the initial render commit.

### Unit 3 — `src/core/ui/timezone-select.tsx`

```tsx
interface TimezoneSelectProps {
  readonly value: string; // IANA zone (e.g., 'America/New_York')
  readonly onChange: (zone: string) => void;
  /** If true and value empty, auto-fills with browser zone on first mount. */
  readonly autoDetect?: boolean;
  readonly disabled?: boolean;
  readonly placeholder?: string;
}
```

Behavior:

- Loads IANA zone list via `Intl.supportedValuesOf('timeZone')` once at module scope (~440 strings, free).
- Groups by region (Africa / America / Antarctica / Arctic / Asia / Atlantic / Australia / Europe / Indian / Pacific / UTC).
- Renders as combobox (uses existing `<Select>` primitive or `cmdk` if grouping/filter is needed). Sticky search input at top.
- If `autoDetect` and `value === ''`, calls `onChange(Intl.DateTimeFormat().resolvedOptions().timeZone)` on mount.
- Each option displays `${zone} (UTC${offset})` — offset computed via `Intl.DateTimeFormat(undefined, { timeZone: zone, timeZoneName: 'shortOffset' })`.

A11y:

- Native `<select>` semantics (or ARIA combobox if `cmdk`).
- The search input has `aria-label="Filter timezones"`.
- Keyboard: Tab navigates options; Enter selects; Escape closes.

### Unit 4 — `useFormatDate` enhancement

Modify `src/core/i18n/use-format.ts`:

```ts
formatDate: (date: string | Date, fmt = 'PPp', timezone?: string) =>
  format(toDate(date), fmt, { locale, /* date-fns supports tz via in-tz pre-shift */ }),
formatDateTime: (date: string | Date, timezone?: string) =>
  new Intl.DateTimeFormat(language, {
    dateStyle: 'short',
    timeStyle: 'short',
    ...(timezone && { timeZone: timezone }),
  }).format(toDate(date)),
formatDateShort: (date: string | Date, timezone?: string) =>
  new Intl.DateTimeFormat(language, {
    dateStyle: 'short',
    ...(timezone && { timeZone: timezone }),
  }).format(toDate(date)),
formatTimeShort: (date: string | Date, timezone?: string) =>
  new Intl.DateTimeFormat(language, {
    timeStyle: 'short',
    ...(timezone && { timeZone: timezone }),
  }).format(toDate(date)),
```

`formatRelative` stays unchanged (relative time has no timezone).

For `formatDate(date, fmt, timezone)`: date-fns' `format()` doesn't support timezone directly. Implementation: pre-convert to the target zone using `Intl.DateTimeFormat(undefined, { timeZone, ... }).formatToParts()` and reassemble, OR accept that `formatDate` is "browser zone only" and document — only `formatDateTime` / `formatDateShort` / `formatTimeShort` get the timezone param. **Decision: only the 3 Intl-based formatters accept `timezone`. `formatDate` (date-fns custom format) and `formatRelative` stay browser-zone for simplicity.**

Backward compatibility: `timezone` is the LAST parameter (optional). Existing callers `formatDateTime(d)` → unchanged. New callers `formatDateTime(d, 'America/Bogota')` → renders in Bogota.

## Library Decision

| Lib                     | Version | Why                                                                          | Bundle (gzip) | Eager? |
| ----------------------- | ------- | ---------------------------------------------------------------------------- | ------------- | ------ |
| `libphonenumber-js/min` | ^1.x    | Industry standard. AsYouType + isValidPhoneNumber. Reduced metadata = small. | ~7 kB         | Lazy   |

**Rejected alternatives:**

| Rejected                     | Reason                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------- |
| `react-phone-number-input`   | Wraps libphonenumber-js but couples to its UI; we want our own Base UI styling  |
| `react-international-phone`  | Same — adds a styled component we'd have to override                            |
| `libphonenumber-js` (full)   | ~25 kB gzip — overkill for our usage which doesn't need exotic country variants |
| Custom phone parser (no lib) | Phone formats are too varied per country to maintain in-house                   |

For timezones, no library — `Intl.supportedValuesOf('timeZone')` is sufficient, returns ~440 IANA strings, browser-native.

## Risks & Mitigations

| Risk                                                                                                                 | Likelihood | Mitigation                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Lazy phone engine load delay causes flicker on first PhoneInput render                                               | M          | Engine loads in microseconds; first paint shows raw input as fallback. Acceptable.                                               |
| `Intl.supportedValuesOf('timeZone')` not supported in older browsers                                                 | L          | Browserlist target is modern (ES2022). All evergreen browsers since 2022 support it.                                             |
| `useFormatDate` timezone arg breaks existing callers due to type widening                                            | L          | New arg is optional; type is `string                                                                                             | undefined`; tests confirm zero-breaking |
| Phone display migration changes layout (e.g., longer string than raw E.164 wraps weirdly)                            | L          | `formatPhone` output is shorter or comparable to raw E.164; spot-check during smoke test                                         |
| `libphonenumber-js/min` doesn't recognize a country that the full build does                                         | L          | `/min` covers 100+ countries common in contact centers; if a tenant needs an exotic country, document upgrade path to full build |
| Browser timezone auto-detect returns weird string (e.g., `"Etc/UTC"` vs `"UTC"`)                                     | L          | TimezoneSelect normalizes via the IANA zone list — any unrecognized string falls back to UTC                                     |
| Currency `toFixed(2)` cleanup in `bot-form.tsx` is for a confidence threshold (not currency) — would break semantics | L          | Verify each cleanup site is monetary; non-monetary `toFixed(2)` stays as-is                                                      |
