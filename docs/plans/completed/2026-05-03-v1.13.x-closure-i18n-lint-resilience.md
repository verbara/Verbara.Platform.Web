# Plan: Cierre del track v1.13.x — i18n + Lint + Resiliencia

**Repo:** `/media/Data/Source/Verbara/Asterisk.Platform.Web/`
**Versión actual:** `1.13.32` (HEAD `1ec9312`, working tree clean)
**Versiones target:** `1.13.33` → `1.13.37` (5 fases, 1 commit + 1 version bump por fase, FCM batching estilo CLAUDE.md)

## Context

El track i18n v1.13.x cerró su Phase 4 mecánica el 2026-05-02 (commit `1ec9312`, “zero hardcoded JSX text en src/”). Pero la revisión profunda post-track encontró que “coverage” es solo una de cinco aristas y que el track NO cumple aún los acceptance criteria del research que lo originó (`docs/research/i18n-coverage-gap-2026-04-28.md`):

| Acceptance criterion                       | Estado real                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------------- |
| Surfaces críticos usan `useTranslation`    | ✅ verificado por sweep                                                               |
| Locale bundle parity (3 locales idénticos) | ❌ **17 keys divergen en `admin.json`**                                               |
| CI guard que bloquee drift                 | ❌ no existe                                                                          |
| Playwright smoke 3 locales                 | ❌ no existe                                                                          |
| Date/number/currency localization auditado | ❌ `useFormatDate`/`useFormatNumber` existen pero consumo no auditado                 |
| Long-tail i18n cerrado                     | ⚠️ 9 archivos sin `useTranslation` (3 admin + 6 analytics) — 78 % cobertura, no 100 % |

Adicionalmente, la auditoría reveló deuda técnica de producción crítica que precede al track i18n:

- **Solo 1 `ErrorBoundary` raíz** (`route-error-boundary.tsx`) → un crash en `/admin/cluster` tumba `/agent` (la superficie de mayor tráfico).
- **Lint backlog real más profundo de lo aparente**: el React Compiler reporta `set-state-in-effect`, `preserve-manual-memoization`, `incompatible-library`, `purity`, `immutability` además de los obvios. 3 falsos positivos en Playwright fixtures están bloqueando ruido legítimo.

Este plan cierra el track v1.13.x con calidad real (no atajos) y deja la base lista para el siguiente minor (`v1.14.0`) que abrirá el track de features customer-facing del backend ya shipped (IP Allowlist v1.15.0, SAML SSO).

**No incluido** en este plan (planes propios futuros, ver “Out of scope” al final).

## Fase 4 — `1.13.36` — Lint priority fix (no sweep total)

**Por qué priorizado:** sweepear los 170 errores incluye refactor de 92 barrel exports + 39 `as any` que son tracks propios. Esta fase mueve los **errores reales que esconden bugs o ruido bloqueante**, defiere los demás con justificación explícita.

### Cambios

1. **Override ESLint para Playwright fixtures** — modificar [eslint.config.js](eslint.config.js):

   ```js
   {
     files: ['tests/e2e/**/*.{ts,tsx}'],
     rules: {
       'react-hooks/rules-of-hooks': 'off',         // 3 falsos positivos: `use` de Playwright vs hook React
       '@typescript-eslint/no-explicit-any': 'off', // ~24 casos en fixtures que tipan handlers de API
     }
   }
   ```

   Net: -27 errores ruidosos.

2. **Fix `react-hooks/set-state-in-effect`** — diagnóstico individual de cada caso (verificado vía `npm run lint | grep set-state-in-effect`). Resolución según patrón:
   - Reseteador de pagination: convertir a derived state o reset programático en handler
   - Sincronización config: useState initializer
   - Crash escenarios: extraer a `useEffect` con dependencies correctas o eliminar el effect

3. **Fix `react-hooks/exhaustive-deps` (11 casos)** — diagnóstico individual:
   - Si la dependencia faltante es real → agregarla
   - Si es intencional → `// eslint-disable-next-line react-hooks/exhaustive-deps` con comentario que explique el porqué (eg. “stable callback, see ADR-X”)

4. **Fix `@typescript-eslint/no-unused-vars` (8 casos)** — eliminar imports/variables no usados (trivial).

5. **Fix `react-hooks/preserve-manual-memoization`** — auditar cada caso. La regla del React Compiler indica que el código memoiza manualmente algo que el compiler ya optimiza. Si el `useMemo`/`useCallback` es redundante, eliminarlo. Si protege algo no detectable estáticamente, `eslint-disable` con comentario.

6. **DEFER explícito** — añadir comentario en [eslint.config.js](eslint.config.js):
   ```js
   // Deferred to track "lint-cleanup-2" (separate plan):
   //   - 92x react-refresh/only-export-components (barrel-export refactor)
   //   - 39x @typescript-eslint/no-explicit-any in src/ (typing audit)
   //   - 8x react-hooks/incompatible-library (third-party compat)
   //   - 1x react-hooks/purity, 1x react-hooks/immutability (case-by-case)
   ```

## Fase 5 — `1.13.37` — Error boundaries por área (replanteamiento del candidato 5)

**Por qué reemplaza al candidato “roadmap”:** el candidato original (SAML SSO, IP Allowlist UI, WebAuthn, SignalR, recording stereo) son features que MERECEN tracks completos en `v1.14.0+`. Específicamente:

- IP Allowlist backend ya shipped en Platform 1.15.0 → requiere bump cross-repo de pin (Web → Platform 1.15.0) + admin UI completa = plan dedicado.
- SAML SSO: backend tiene `OidcEndpoints.cs` + `PlanFeature.OidcSso` pero el frontend necesita login flow + management page = plan dedicado.

Mientras tanto, **error boundaries por área** es un gap de robustez de producción identificado en la auditoría: solo hay `<RouteErrorBoundary>` en [src/main.tsx](src/main.tsx). Un componente que crashea dentro de `/admin/cluster` lleva a la pantalla de error global y tumba `/agent`, que es el surface de mayor tráfico en producción. Trabajo de bajo esfuerzo, alto impacto en UX.

### Cambios

1. **Crear `src/core/ui/area-error-boundary.tsx`** — boundary con prop `areaName` que muestra mensaje contextual (“Algo falló en el módulo de Administración”) en lugar de tumbar toda la app. Reusa la estructura de [src/core/ui/route-error-boundary.tsx](src/core/ui/route-error-boundary.tsx) — debe ser una clase `Component` (los hooks no funcionan en error boundaries) y usar `i18n.t()` directamente como ya hace `route-error-boundary.tsx` (precedente del Phase 4O-3).

2. **Wrap cada layout shell** — en [src/pages/admin-layout.tsx](src/pages/admin-layout.tsx), [src/pages/agent-layout.tsx](src/pages/agent-layout.tsx), [src/pages/analytics-layout.tsx](src/pages/analytics-layout.tsx), [src/pages/operations-layout.tsx](src/pages/operations-layout.tsx):

   ```tsx
   <AreaErrorBoundary areaName="admin">{/* ... existing layout content ... */}</AreaErrorBoundary>
   ```

3. **Keys i18n** — añadir a `common:errors`:
   - `area_error_title` — “Something went wrong in this section”
   - `area_error_message` — “The {{areaName}} module failed to load. Other parts of the app are still available.”
   - `back_to_home` — “Go to home”

4. **Test E2E** — `tests/e2e/tests/error-boundaries/area-isolation.spec.ts`:
   - Forzar un crash en una ruta `/admin/...` (vía `page.evaluate(() => { throw new Error('test') })` injection o `page.route` interceptor que devuelva 500)
   - Verificar que la pantalla de error de área aparece (no la global)
   - Navegar a `/agent` y verificar que carga normalmente

### Verificación

npx playwright test tests/e2e/tests/error-boundaries/area-isolation.spec.ts

## Out of scope (planes futuros, NO en este plan)

Reportados explícitamente para no perderse de vista:

### v1.14.0 (siguiente minor) — features customer-facing

1. **Bump pin Platform 1.14.6 → 1.15.0** + **IP Allowlist admin UI**: backend listo (15 commits, 4 endpoints CRUD + middleware + spec en Platform). Plan dedicado: spec design del UI, hook `use-tenant-ip-allowlist.ts`, page `/admin/security/ip-allowlist`, integración con permission `system:tenant:configure`.

2. **SAML SSO admin UI**: backend tiene `OidcEndpoints.cs` + `PlanFeature.OidcSso`. Plan dedicado: hook + management page + login flow extension.

3. **Bundle chunk consolidation**: 9 chunks > 500 kB sin `manualChunks` config. Plan dedicado para configurar [vite.config.ts](vite.config.ts) con grupos lógicos (vendor-react, vendor-charts, vendor-grid, vendor-i18n, vendor-flow). Mejora LCP measurable.

### Tracks de calidad (separados)

4. **Track lint-cleanup-2**: refactor de los 92 `react-refresh/only-export-components` (separar barrel exports de componentes) + 39 `@typescript-eslint/no-explicit-any` en `src/` (typing audit). Esfuerzo medio (~3-5 días). No bloquea producto.

5. **Track typescript-strict-2**: 31 `as any | as unknown as` casts + 28 archivos con `@ts-ignore` en `src/`. Probablemente correlacionado con `as any` del lint-cleanup-2.

6. **Track api-hooks-test-coverage**: 54 hooks en [src/core/api/hooks/](src/core/api/hooks/), 9 con tests. 45+ hooks sin cobertura. Esfuerzo grande (~10-15 días). Requiere MSW o handlers fake. Plan dedicado.

7. **Track a11y-foundations**: 0 skip-to-content links, 0 a11y tests automation. Plan dedicado: `axe-playwright`, skip-link en shell, keyboard nav audit.

### Bloqueados por backend

8. **WebAuthn enrollment**: backend deferred per Platform roadmap.

9. **User-level language preference (server-side)**: requiere endpoint nuevo `/api/v1/users/me/preferences` en Platform. Hoy `TenantSettings.Locale` es solo per-tenant.

10. **Recording stereo channel selector**: endpoint backend `MapRecordingEndpoints` existe pero sin selector stereo específico — coordinar con SDK team antes de Web work.
