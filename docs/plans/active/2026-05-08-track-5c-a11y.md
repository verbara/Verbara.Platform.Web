# Track 5C-a11y — Accessibility Foundation (Spec)

- **Date:** 2026-05-08
- **Status:** Draft → pending user approval
- **Roadmap:** [v1.14.x Operational Foundation](2026-05-03-v1.14.x-operational-foundation-roadmap.md), Nivel 5, Track 5C (a11y portion)
- **Target version:** `v2.0.4-web` (2-patch track: `2.0.3`, `2.0.4`)
- **Predecessor:** Track 5B Virtualization (closed 2026-05-08, tag `v2.0.2-web`)
- **Sibling deferred:** Track 5C-export (print stylesheets + PDF export) — separate track, post-5C-a11y

## Goal

Bring the web app to WCAG 2.1 AA compliance on the dimensions where current gaps are flagrant, by adding two reusable a11y primitives, a centralized form-error wiring layer, automated lint + E2E coverage, and targeted edits across components. Prevent regressions by activating `eslint-plugin-jsx-a11y` in CI.

## Scope decision

The roadmap literal listed five items: aria-live, skip-link, axe-core, prefers-reduced-motion, critical-alerts. An exhaustive WCAG 2.1 AA audit revealed gaps the roadmap missed that are equally or more impactful:

- **`disabled:opacity-50` on `Button`** drops contrast below AA on 150+ disabled-button instances
- **86 files using react-hook-form patterns** lack `aria-describedby` linking inputs to error messages (56 already wire `aria-invalid` partially; the missing piece is the message-id linkage)
- **`<html lang>`** is hardcoded to `"en"` and never updates when i18n switches locale
- **50+ DataTable headers** missing `scope="col"`
- **LoadingOverlay/Skeleton** missing `aria-busy`
- **Error boundaries** lack `role="alert"` and focus management
- **~10 search/utility inputs** lack a visible `<Label>` AND lack `aria-label` (true violation; e.g., `data-table.tsx` search input). The audit's claim of "8+ forms with placeholder-only labels" was a false positive — `basic-step.tsx` and `partner-rate-card-form.tsx` (cited examples) already have proper `<Label htmlFor>` pairs. The real cases are search-and-filter inputs and a small set of utility inputs (`mfa-verify.tsx`, `flow-toolbar.tsx`, etc.)
- **10–15 detail pages** skip heading levels (h1 → h3)
- **No `eslint-plugin-jsx-a11y`** in CI — every regression today ships unflagged

Doing only the roadmap literal would close 5C-a11y while leaving these flagrant violations in place. The honest scope is the union of roadmap items + audit CRITICAL/HIGH gaps.

### Primitive APIs

**`<SkipLink>`:**

```tsx
interface SkipLinkProps {
  readonly targetId: string;
  readonly children: ReactNode;
  readonly className?: string;
}
// Render: <a href={`#${targetId}`} className={cn('sr-only focus:not-sr-only focus:absolute focus:top-2 focus:left-2 focus:z-50 focus:rounded focus:bg-background focus:px-3 focus:py-2 focus:text-foreground focus:shadow', className)}>{children}</a>
```

**`<LiveRegion>`:**

```tsx
interface LiveRegionProps {
  readonly politeness?: 'polite' | 'assertive'; // default 'polite'
  readonly atomic?: boolean; // default true
  readonly children: ReactNode;
  readonly className?: string; // typically 'sr-only'
}
// Render: <div role={politeness === 'assertive' ? 'alert' : 'status'} aria-live={politeness} aria-atomic={atomic} className={cn('sr-only', className)}>{children}</div>
```

### Form a11y helpers (no shadcn `<FormField>` exists in this repo)

The repo does NOT use shadcn's Form wrapper. Forms hand-assemble `<Label htmlFor="x">` + `<Input id="x" {...register('x')} />` + `{errors.x && <p>...</p>}` directly with react-hook-form. Building a wrapper-from-scratch and migrating 86+ files is out of Track 5C-a11y scope.

Instead, ship two small opt-in helpers that align with the existing pattern:

**`useFieldA11y(error, baseId)` hook in `src/core/hooks/use-field-a11y.ts`:**

```ts
export function useFieldA11y(error: { message?: string } | undefined, baseId: string) {
  const errorId = `${baseId}-error`;
  return {
    inputProps: {
      'aria-invalid': error ? true : undefined,
      'aria-describedby': error ? errorId : undefined,
    } as const,
    errorId,
  };
}
```

**`<FieldError>` component in `src/core/ui/field-error.tsx`:**

```tsx
interface FieldErrorProps {
  readonly id: string;
  readonly message?: string;
  readonly className?: string;
}
function FieldError({ id, message, className }: FieldErrorProps) {
  if (!message) return null;
  return (
    <p id={id} role="alert" className={cn('text-xs text-destructive', className)}>
      {message}
    </p>
  );
}
```

**Usage at the call-site (5–7 line edit per form):**

```tsx
const emailA11y = useFieldA11y(errors.email, 'user-email');
// ...
<Label htmlFor="user-email">{t('email')}</Label>
<Input id="user-email" {...register('email')} {...emailA11y.inputProps} />
<FieldError id={emailA11y.errorId} message={errors.email?.message ? t(errors.email.message) : undefined} />
```

**Coverage strategy:** apply to forms in priority order (visible/critical first):

- Tier 1 (5C.2 must): login, mfa-verify, forgot-password, reset-password, user-form, queue-form, agent-step, MFA setup
- Tier 2 (5C.2 should): partner-rate-card-form, campaign basic-step, route-form, system-page, knowledge editor
- Tier 3 (followup): bot config, survey editor, retention rules, etc. (numerous, lower-traffic). The hook is generic so partial adoption is fine — uncovered forms work as today.

**Acceptance for Tier 1 forms:** every input with a registered field has `useFieldA11y` wired AND `<FieldError>` rendered. `npm run lint` (with jsx-a11y) passes. Manual screen-reader smoke test on one form (login).

### Reduced-motion CSS block

In `src/index.css`:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Targets `animation-*` and `transition-*` only. Does not break `setTimeout`-based logic. The `!important` is the canonical way to override Tailwind's per-utility durations.

### Button disabled fix

Current (`src/core/ui/button.tsx`): `disabled:pointer-events-none disabled:opacity-50`.

New: `disabled:pointer-events-none disabled:cursor-not-allowed disabled:bg-muted disabled:text-muted-foreground disabled:border-muted` (variant-by-variant). Verify ≥ 4.5:1 contrast with browser DevTools accessibility inspector.

### `<html lang>` sync

In `src/core/i18n/language-switcher.tsx` (or in i18n init):

```tsx
useEffect(() => {
  document.documentElement.lang = i18n.language;
}, [i18n.language]);
```

Initial render: `index.html` keeps `lang="en"` as fallback; the effect updates immediately on app boot.

### Error boundary focus

`ErrorBoundary` is a class component (`extends Component<Props, State>`). Add a ref on the container, `role="alert"` + `tabIndex={-1}`, and trigger focus from `componentDidUpdate` when `state.hasError` flips to true. `RouteErrorBoundary` is a function component — same pattern with `useRef` + `useEffect` keyed on `error?.message`.

### Sonner toast container

Sonner v2.0.7 already provides `aria-live` and `role="status"` on each toast and a default `aria-label` on the container. The relevant prop in v2.0.7 is `containerAriaLabel`; set it i18n-aware so the container itself has a localized accessible name. Example:

```tsx
const { t } = useTranslation();
return <Sonner containerAriaLabel={t('a11y.notificationsRegion')} {...props} />;
```

Add the i18n key `a11y.notificationsRegion` to all three locales' `common.json`.

### InboxPanel announcer

Add a `useEffect` watching `visible.length`. When a new conversation appears (length grew + the first item id is not the previously-tracked first id), set local state with the announcement string. Render `<LiveRegion politeness="polite" className="sr-only">{announcement}</LiveRegion>` in the panel.

i18n key: `agent.inbox.announceNew` — `"New conversation from {{name}}"` / `"Nueva conversación de {{name}}"` / `"Nova conversa de {{name}}"`.

## Risks

### R1 — `jsx-a11y` cascade of warnings (HIGH)

The `recommended` preset can flag 30+ violations on first activation (icon-only buttons missing `aria-label`, redundant alt text, etc.). Mitigation: rollout in three steps inside 5C.1 (warn → fix → error). If the violation count exceeds ~50, sub-divide 5C.1 into 5C.1a (tooling, warn-only) and 5C.1b (fix sweep + promote). Re-evaluate after the first run.

### R2 — Form a11y helper adoption tier coverage (MEDIUM)

86+ forms exist; Tier 1 covers ~8 of them. Tier 2/3 remain on the followup track. Mitigation: the helpers are non-invasive (uncovered forms continue to work), Tier 1 covers the user-facing critical flows (auth, account creation), and `eslint-plugin-jsx-a11y` will surface raw violations elsewhere. Followup track scope is documented at closure.

### R3 — Disabled button contrast affects dark mode differently (MEDIUM)

`bg-muted` + `text-muted-foreground` over both light and dark themes need contrast verification. Mitigation: Chrome DevTools accessibility inspector on at least 3 button variants (default, destructive, outline) in both themes. Document the measured ratios in the closing commit.

### R4 — `prefers-reduced-motion: reduce` over-broadly affects functional motion (LOW)

The block uses `!important` on `animation-*` and `transition-*` only. Animations that act as functional indicators (e.g., loading spinners, the skeleton pulse) remain functionally fine because they're indicating loading state, not conveying motion-based information. The user with `reduce` preference has explicitly opted out of those visual cues; the `aria-busy` + sr-only text adopted in 5C.2 cover the equivalent semantics.

### R5 — axe-core baseline spec hits authenticated routes (MEDIUM)

Mitigation: use existing `auth.fixture.ts`. Six routes selected: `/login` (unauthenticated), then 5 routes via `platformAdminPage` and `agentPage` fixtures.

### R6 — Heading hierarchy fixes break visual styling (LOW)

Demoting an `<h3>` to `<h2>` may affect Tailwind class auto-applied to headings (rare in this repo — inline classes used). Mitigation: per-page review during 5C.2.
